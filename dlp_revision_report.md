## 2. Persistence Layers

### 2.1. SQLite Fallback (Failover Persistence)
The system employs an automatic failover mechanism for the primary database.
- **Location**: `packages/persistence/session.py`
- **Logic**: If the PostgreSQL connection (`DATABASE_URL`) fails, the system initializes a local SQLite instance at `runtime/data/cortex_local.db`.
- **Integrity**: `Base.metadata.create_all` is called lazily to ensure the schema is always present.

### 2.2. Atomic JSON Memory (Corruption Protection)
JSON-based memory stores (like `ChannelStore`) implement atomic write operations to prevent file corruption.
- **Location**: `packages/memory/store.py`
- **Mechanism**:
    1. Writes to a hidden temporary file (.tmp).
    2. Performs a POSIX-compliant `os.replace` (atomic operation).
- **Benefit**: Even if power is lost during a write, the system retains the previous valid state instead of a partial/broken file.

### 2.3. Docker Volume Hardening (Infrastructure Persistence)
Runtime state is explicitly isolated from container volatility.
- **Volume**: `runtime_data`
- **Mapping**: `/app/runtime/data`
- **Protected Assets**:
    - `cortex_local.db` (SQLite Database)
    - `channel_store.json` (Signal mappings)
    - Local backups and logs.
